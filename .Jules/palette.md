## 2024-11-20 - Custom Progress Bar ARIA Management and Keyboard Focus
**Learning:** For custom DOM-based progress bars (e.g. `div` based ones instead of native `<progress>`), simply setting `role="progressbar"` and static `aria-valuemin`/`aria-valuemax` attributes is not enough. The `aria-valuenow` attribute must be actively managed by JavaScript in synchronization with the visual updates (like changing the CSS width) so screen readers get the current value. In addition, interactive elements such as `a` and `select` must have explicitly defined `:focus-visible` CSS rules to ensure clear keyboard navigation visibility.
**Action:** When implementing or fixing custom progress bars, verify that JavaScript updates `aria-valuenow` alongside visual changes. Always ensure `:focus-visible` styles are explicitly set for interactive elements in the styling block.
